# GAN-upscale

Увеличение разрешения изображений в 4 раза (super-resolution ×4) с помощью GAN в стиле SRGAN на PyTorch. Обучение и проверка — на датасете DIV2K. Дополнительно — U-Net для доработки результата GAN и сравнение с классическими фильтрами OpenCV.

```
LR 64×64 ──► Генератор ──► SR 256×256 ──► Дискриминатор: «настоящая или сгенерированная?»
                  ▲                │
                  └── VGG19 сравнивает SR и оригинал HR по признакам (perceptual loss)
```

## Структура проекта
```
GAN-upscale/
├── train.py               # обучение GAN: модели, датасет, цикл обучения, валидация
├── infer.py               # апскейл папки изображений обученным генератором
├── evaluate.py            # PSNR / SSIM результата относительно оригинала (+ сравнение с фильтрами)
├── filter_images.py       # применить фильтр OpenCV ко всем изображениям папки
├── split_samples.py       # нарезка примеров из images/ на res/hr, res/lr, res/gr (данные для U-Net)
├── unet.py                # U-Net (Keras): доработка выхода GAN
├── pixel_mlp_rgb.py       # ранний эксперимент (Keras): сеть по окрестности 3×3 пикселя, RGB целиком
├── pixel_mlp_channels.py  # то же, по каждому каналу отдельно
├── check_gpu.py           # проверка, видит ли PyTorch видеокарту
├── requirements.txt
├── data/                  # датасет DIV2K (не в git, см. «Данные»)
├── images/                # примеры HR | LR | SR, сохраняемые во время обучения (не в git)
├── res/                   # результаты infer.py, split_samples.py, unet.py (не в git)
├── saved_models/          # веса: новые .pth от train.py (не в git) и старые .h5 Keras-моделей
└── pretrained/            # веса старой версии GAN (несовместимы с текущим кодом)
```

## Модели
| Модель | Где | Для чего |
|---|---|---|
| **Генератор** | `train.py`, `GeneratorResNet` | Основная модель: превращает картинку низкого разрешения в картинку в 4 раза больше |
| **Дискриминатор** | `train.py`, `Discriminator` | Нужен только при обучении: отличает настоящие HR от сгенерированных и заставляет генератор рисовать правдоподобные детали |
| **VGG19** | `train.py`, `FeatureExtractor` | Нужна только при обучении: сравнивает результат с оригиналом по признакам (perceptual loss), а не по пикселям — так картинка получается резче |
| **U-Net** | `unet.py` | Отдельный эксперимент: дорабатывает уже увеличенную GAN картинку |
| **Pixel MLP** | `pixel_mlp_*.py` | Ранний эксперимент, не поддерживается |

### Генератор (~1.5 млн параметров)
Архитектура SRResNet без BatchNorm (как в EDSR):
- свёртка 9×9 → 64 канала + PReLU;
- 16 residual-блоков (свёртка 3×3 → PReLU → свёртка 3×3, плюс пропускающее соединение) и общее пропускающее соединение вокруг них;
- 2 блока увеличения ×2: свёртка в 256 каналов → PixelShuffle → PReLU;
- свёртка 9×9 → 3 канала.

Сеть предсказывает не картинку целиком, а **детали поверх бикубического увеличения**: `выход = bicubic(LR) + поправка`. Поэтому уже с первых эпох результат не хуже обычной интерполяции.

### Дискриминатор (~4.7 млн параметров)
4 блока (64 → 128 → 256 → 512 каналов): свёртки 3×3, BatchNorm, LeakyReLU, уменьшение в 2 раза в каждом блоке. На выходе — карта 16×16 оценок «настоящий / сгенерированный» для отдельных участков картинки (PatchGAN). Функция потерь — MSE (LSGAN).

### VGG19
Предобученная на ImageNet, заморожена; используются первые 18 слоёв (до `relu3_4`). Веса (~550 МБ) скачиваются автоматически при первом запуске.

### Обучение
1. **Предобучение** (`pretrain_epochs`, по умолчанию 20): генератор учится только на попиксельной ошибке L1 — восстанавливает цвета и форму. Дискриминатор и VGG не используются.
2. **GAN** (`n_epochs`, по умолчанию 30): ошибка генератора = L1 по признакам VGG + 0.001 × adversarial + 1.0 × попиксельная L1. Дискриминатор учится параллельно.

Обучение идёт на случайных фрагментах 64×64 (LR) / 256×256 (HR) с отражением по горизонтали, batch size 4, Adam (lr 1e-4). После каждой эпохи считается PSNR на 100 валидационных картинках.

### U-Net и классические фильтры
- **U-Net** (`unet.py`, Keras): 2 уровня уменьшения (32 → 64 канала), bottleneck 128, 2 уровня увеличения со skip-соединениями. Вход — выход GAN, цель — оригинал. Выборка делится на train/test 80/20.
- **Фильтры** (`evaluate.py --filters`, `filter_images.py`): медианный, гауссов, двусторонний (3×3, 5×5, 9×9) и повышение резкости — чтобы проверить, улучшает ли простая постобработка результат GAN.

## Данные
[DIV2K](https://data.vision.ee.ethz.ch/cvl/DIV2K/): 800 картинок для обучения, 100 для валидации, LR получены бикубическим уменьшением в 4 раза. Ожидаемая структура:
```
data/DIV2K_train_HR/            0001.png … 0800.png
data/DIV2K_train_LR_bicubic/X4/ 0001x4.png … 0800x4.png
data/DIV2K_valid_HR/            0801.png … 0900.png
data/DIV2K_valid_LR_bicubic/X4/ 0801x4.png … 0900x4.png
```
Пары LR/HR сопоставляются по имени файла. Пути считаются от папки проекта, поэтому скрипты можно запускать из любой директории.

## Установка

### 1. PyTorch с поддержкой видеокарты
Обучать на CPU не имеет смысла — нужна NVIDIA GPU и PyTorch, собранный с CUDA. Обычный `pip install torch` на Windows ставит CPU-версию, поэтому сначала:
```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126
```

### 2. Остальные зависимости
```bash
pip install -r requirements.txt
```
TensorFlow нужен только для `unet.py` и `pixel_mlp_*.py`. Если он не ставится на вашу версию Python, используйте для U-Net отдельное окружение с более старым Python (например, 3.12).

### 3. Проверка видеокарты
```bash
python check_gpu.py
```
Ожидаемый вывод — `Сборка с CUDA: 12.6`, имя видеокарты и `Тест вычислений на GPU: OK`.
- `Сборка с CUDA: нет` — установлена CPU-версия PyTorch, переустановите командой из шага 1.
- Сборка с CUDA есть, но GPU не найдена — проверьте драйвер командой `nvidia-smi`.

`train.py` при старте тоже печатает, на чём идёт обучение (`GPU: ...`), и предупреждает, если видеокарта недоступна.

## Запуск

### Обучение
```bash
python train.py
```
Параметры задаются в начале `train.py`: `pretrain_epochs`, `n_epochs`, `pixel_weight`, `batch_size`, `lr`, размер фрагмента `hr_height` / `hr_width`. На RTX 3060 Laptop эпоха занимает ~1 минуту при ~1.5 ГБ видеопамяти, всё обучение (50 эпох) — около часа.

Веса сохраняются в `saved_models/`:
- `generator_pretrain.pth` — после предобучения: максимальный PSNR, но картинка мягче;
- `generator_best.pth` — лучший по PSNR в GAN-фазе: детали резче;
- `generator_last.pth`, `discriminator_last.pth` — последняя эпоха. Чтобы продолжить обучение с них, поставьте `load_pretrained_models = True`.

Примеры «оригинал | бикубическое увеличение | результат GAN» сохраняются в `images/` каждые 200 батчей.

### Увеличение изображений
```bash
python infer.py --weights saved_models/generator_best.pth --input data/DIV2K_valid_LR_bicubic/X4 --output res/gan
```
Результат сохраняется под именем оригинала (`0801x4.png` → `0801.png`). Большие картинки обрабатываются кусками по `--tile 128` пикселей LR, чтобы поместиться в память GPU; если памяти не хватает, уменьшите `--tile`.

### Оценка качества
```bash
python evaluate.py --hr data/DIV2K_valid_HR --sr res/gan
python evaluate.py --hr data/DIV2K_valid_HR --sr res/gan --filters   # + результат после каждого фильтра
```
PSNR и SSIM считаются по всем трём каналам RGB; пары подбираются по имени файла.

### Постобработка фильтром
```bash
python filter_images.py --input res/gan --output res/gan_gaus-9x9 --filter gaus-9x9
```
Доступные фильтры: `med-3x3`, `med-5x5`, `med-9x9`, `gaus-3x3`, `gaus-5x5`, `gaus-9x9`, `bila-3x3`, `bila-5x5`, `bila-9x9`, `sharpen`.

### U-Net поверх GAN
```bash
python train.py            # примеры HR | LR | SR в images/
python split_samples.py    # нарезка на res/hr, res/lr, res/gr
python unet.py             # обучение U-Net, результат на тестовой части в res/UNET
python evaluate.py --hr res/hr_test --sr res/UNET
```

## Результаты
После короткого тестового обучения (3 эпохи предобучения + 2 эпохи GAN) на 5 полноразмерных валидационных картинках:

| Метод | PSNR, дБ | SSIM |
|---|---|---|
| Бикубическое увеличение | 25.14 | 0.721 |
| GAN | 25.49 | 0.737 |

Полное обучение (50 эпох) ещё не проводилось.

## Старые веса
- `pretrained/` — генератор и дискриминатор старой версии (разные даты экспериментов в подпапках).
- `saved_models/unet.h5`, `pixel_mlp.h5`, `pixel_mlp_v1.h5` — веса Keras-моделей.

Все они получены со старым кодом с ошибками (см. ниже) и с текущими моделями несовместимы — модели нужно переобучить.

## Исправленные ошибки
- Генератор учился только по признакам VGG — цвета ничем не ограничивались, на выходе была зелёная рябь. Добавлены предобучение на попиксельной ошибке (как в статье SRGAN) и попиксельная составляющая в GAN-фазе.
- С BatchNorm и выходом «картинка целиком» генератор учился хуже бикубической интерполяции (21 дБ против 25). Теперь генератор без BatchNorm и предсказывает только детали поверх бикубического увеличения.
- Данные нормализовались по ImageNet (≈ [-2.1, 2.6]), а генератор с `Tanh` выдавал [-1, 1]. Теперь данные в [-1, 1], а нормализация ImageNet делается только внутри VGG.
- `BatchNorm2d(n, 0.8)` задавал `eps=0.8` вместо `momentum` — исправлено.
- LR/HR пары сопоставлялись по порядку `glob`, а фрагменты могли не совпадать — теперь пары по имени, фрагменты по согласованным координатам.
- Чекпоинты перезаписывали `pretrained/` и выбирались по ошибке одного батча — теперь `saved_models/` и выбор по PSNR на валидации.
- Метрики считались на обучающих картинках, после min-max нормализации, только по красному каналу, SSIM с неверным `data_range`, пары подбирались по порядку `listdir` — всё исправлено в `evaluate.py`.
- U-Net обучалась и проверялась на одних и тех же картинках — теперь отдельная тестовая часть.
